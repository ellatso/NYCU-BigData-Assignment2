## Model and matched explanatory experiments

Six LightGBM binary heads, fixed seed42,160 trees, learning rate .045,23 leaves, minimum leaf support30,L2=4. Training is deterministic and single-threaded. If a training target has only one class, its head uses that observed constant probability instead of fitting an invalid binary classifier. IDs are used only for joins and output alignment, never as numerical model inputs.

Configured split origins (Taiwan midnight): train Sep10/Sep17; calibrate Oct1/Oct8; evaluate Oct22/Oct29. Labels cover seven days. Each origin simulates a four-hour observation gap. The preceding split's outcomes end before the next split's cutoff. The submission prototype is **fixed in advance as dynamic_relations** (43 temporal plus32 dynamic relation inputs). Thresholds use calibration only. The best calibration reference is also reported separately, with exact ties favoring fewer inputs. This educational design choice is not a claim that the relational prototype maximizes F1. The policy is recorded before development scoring. These fixed historical choices are explanatory development experiments, not an untouched final test.

Ablations share dates, observed cohort population, labels, model hyperparameters and selection procedure:

| Variant | Question answered |
|---|---|
| Observed-history features | What can user age and counts since collection start explain? |
| Recent7 | How much does recent activity add? |
| Temporal30 | What do7/14/30-day windows, recency and trend add? |
| No recency / no trend | Which temporal components matter? |
| Static relations | What does aggregate FK neighborhood information add? |
| Temporal + static relations | Does adding neighborhood information to the temporal baseline help? |
| Received interactions | Do comments/reviews received on authored objects add information? |
| Dynamic relations | Do short author/repo/collaborator windows help? |
| No peer relations | Are collaborator signals responsible for a difference? |
| Availability clock | How does counting newly visible records differ from occurrence-time windows? |
| Last-week rule | Is complexity justified relative to a simple rule? |

This is **relational aggregation followed by trees**, not a GNN or end-to-end RDL. Received interactions join comments/reviews to visible PR/issue authors and exclude self interactions. Repo activity excludes own contributions. Cohort-peer activity does not assume that non-cohort users are fully observed. A stale/missing archive or incomplete warmup can affect every ablation; the report retains those limitations.

## Time, labels and cold starts

Rows and FK endpoints must be visible by the feature cutoff. Occurrence-time windows do not grant access to rows learned later. Later-known merged/closed/dismissed fields are excluded from modeling. Historical outcome labels require both an occurrence inside the outcome week and row availability before outcome end. GH Archive collection gaps mean these are **observed reconstructed outcomes**, not guaranteed complete truth. File/hour coverage and delayed-availability statistics are saved separately.
